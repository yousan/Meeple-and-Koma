# 仕様書：傘の持ち忘れ防止アプリ

最終更新：2026-11-14 ／ 開発期間：1週間

> `（仮）` と書かれた値は初期案です。実機で試しながらチームで調整してください。

## 1. 目的

傘の持ち忘れ・置き忘れによる「ずぶ濡れ」をなくす。
やらかし集 No.4（天気を見ずに出て濡れた）と No.10（傘を家とコンビニに忘れた）を解決する。

## 2. スコープ

| フェーズ | 内容 | 優先度 |
|---|---|---|
| 1 | 天気取得、雨予報の通知、設定、通知履歴、「傘を持った」ボタン | 必須 |
| 2 | 傘立てセンサー連携（IoT） | できれば |
| 3 | スマートタグ併用の案内（簡易） | 余裕があれば |

**範囲外**：アプリからBluetoothで傘を直接検知する機能（Web/PWAでは制約が大きいため）

## 3. 画面構成

| 画面 | 内容 |
|---|---|
| ホーム | 今日の天気、降水確率、傘が必要かの一目表示、「傘を持った」ボタン |
| 設定 | 通知時刻、対象時間帯、地域、降水確率のしきい値、通知方法 |
| 通知履歴 | 過去の通知、「持った／持たなかった」の記録 |
| 傘の状態 | 傘立てセンサーの状態、最終確認時刻、スマートタグの案内（フェーズ2・3） |

各画面で、次の状態の表示を用意する。
- 空の状態（データがまだない）
- 雨の日／晴れの日
- エラー時（天気取得失敗、通知が許可されていない など）

## 4. 通知仕様

### 4.1 通知の種類

| 種類 | タイミング | 条件 |
|---|---|---|
| 出発前通知 | 設定した通知時刻（例：7:30（仮）） | 対象時間帯のいずれかで降水確率がしきい値以上 |
| 帰宅前通知 | 設定した帰宅前時刻（例：授業終了の30分前（仮）） | 帰宅時間帯に降水確率がしきい値以上 |
| 強化通知（IoT） | 出発前通知の後、出発時刻の前 | 雨予報 ＋ 傘が傘立てにある状態 |

### 4.2 判定ルール

- 降水確率のしきい値の初期値：**50%（仮）**（設定画面で変更可能）
- 対象時間帯：ユーザーが設定した外出〜帰宅の時間帯
- 雨が予想されない日は通知しない

### 4.3 通知文面（案）

- 出発前：「今日は午後から雨の予報です。傘を持ちましたか？」
- 帰宅前：「帰りに雨が降りそうです。傘の準備はOKですか？」
- 強化通知：「雨予報なのに、傘が傘立てに残っています」

通知から「傘を持った」を1タップで記録できるようにする。

## 5. 技術構成

| 項目 | 内容 |
|---|---|
| アプリ形態 | PWA（HTML/JS、またはReact） |
| 天気API | Open-Meteo（キー不要）、または気象庁のデータ |
| サーバー | Firebase（Firestore + Cloud Functions）またはSupabase |
| 通知 | まずLINE / Discordで動作確認 → 余裕があればWeb Push |
| IoT受信 | サーバーのHTTPエンドポイント |

### 5.1 端末対応の注意（iPhoneが主）

- iPhoneでは、**Safariで開いて「ホーム画面に追加」したPWAのみ**Web Pushが届く（iOS 16.4以降）
- 初回起動時に、ホーム画面への追加手順と通知許可を案内する画面を用意する
- 動作確認は**iPhone実機**で行う（Android担当者の端末だけでは確認できない）
- 通知が不安定な場合に備え、LINE / Discord通知を代替手段として残す

## 6. IoT連携仕様（フェーズ2）

### 6.1 データ形式（ハード → サーバー）

```json
{
  "device_id": "umbrella_stand_01",
  "umbrella_present": true,
  "timestamp": "2026-11-14T07:30:00+09:00"
}
```

- 傘の状態が変わったときに、HTTP POSTで送信する
- 認証：簡易トークン（ヘッダーで送る）を想定（詳細は未決）

### 6.2 アプリ側の動作

- 「傘あり ＋ 雨予報 ＋ 出発時刻が近い」で強化通知を出す
- ハードが間に合わない場合に備え、**「傘あり／なし」を手動で切り替えるデバッグボタン**を用意する（デモ保険）

### 6.3 ハード担当への依頼事項

- 傘の有無の検知方法（距離・重量・スイッチなど）の決定と共有
- 使用マイコン（ESP32など）と通信方式の確認
- 初日にこのJSON形式で合意する

## 7. 置き忘れ防止（スマートタグ併用・フェーズ3）

置き忘れ通知は、**タグ側のアプリが出す**。本アプリはタグの状態を読み取らない。

| 項目 | 内容 |
|---|---|
| 本アプリの役割 | 初回の設定案内、通知文面での呼びかけ、傘の状態画面での案内 |
| タグの選択 | チームの端末がiPhone中心なら**AirTag**が有力。AndroidとiPhone両方で使いたい場合は**Tile**（機能や料金プランは購入前に要確認） |
| 注意 | AirTagはiPhone専用。Android担当者の端末では置き忘れ通知を確認できない |
| デモ前の確認 | 実際に傘から離れたときの通知タイミングを、iPhone実機で確認する |

### 発表での説明

「市販スマートタグと連携した運用」と説明する（アプリが直接制御しているとは言わない）。
IoTとして見せるのは傘立てセンサーの部分とする。
